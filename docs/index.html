The four ways AWS bills usually go wrong.

📈 The bill is a surprise

You find out you overspent when the invoice arrives, weeks too late to do anything about it.

🔥 Something ran for weeks

A test cluster or GPU instance was left on. Nobody noticed until month-end.

❓ Nobody owns the spend

Half the resources have no owner tag, so no team can see or cut its own costs.

🌙 Paying for empty hours

Dev and test servers run all night and all weekend, when nobody is using them.

Six guardrails, one rollout

Each is a small Terraform module. Use one or all of them.

See

Budgets

Alerts at 50%, 80% and 100% of your monthly budget, and when AWS forecasts you'll go over. Per-service budgets too.

See

Cost anomaly detection

AWS machine learning flags unusual spend in any service, so a runaway resource is caught within about a day.

Attribute

Tag enforcement

Finds untagged resources and, if you choose, standardises Owner / Environment / CostCenter tags across the organization.

Cut

Off-hours scheduler

Stops tagged dev/test EC2, RDS and Aurora at night and starts them in the morning. Dry-run first. Production is never touched.

Cut

S3 lifecycle

Moves ageing data to cheaper storage classes and cleans up old versions and failed uploads. Never deletes current data by default.

Automate

Keyless CI/CD

GitHub Actions deploys with short-lived credentials. Every change gets a plan on the pull request and an approval before it ships.

The four-week rollout

Small, safe steps. You see value in the first week.

Week 1

See the money

Budgets and anomaly alerts go live in Slack, Teams or email. Baseline taken from Cost Explorer.

Week 2

Find the waste

Review the top cost drivers with your team. Agree which dev/test resources can sleep at night.

Week 3

Attribute every dollar

Tag rules and cost allocation tags, so every team can see its own spend.

Week 4

Cut and hand over

Scheduler moves from dry-run to live, S3 tiering is enabled, CI/CD is set up, and your team gets a handover session.

Built to be trusted

The code is public, so you can check every claim.

  • Tested on every change. 33 Terraform tests, 12 Lambda tests, linting and a security scan, all required before merge.
  • Least privilege. The scheduler can only stop resources that carry the opt-in tag, and AWS IAM enforces it.
  • Safe defaults. Nothing is deleted, stopped or blocked unless you turn it on.
  • No lock-in. MIT-licensed Terraform in your own repository. You keep everything.
  • Every security exception explained. Each skipped scanner finding has a written cost or risk reason.
  • Supply-chain safe CI. GitHub Actions pinned to exact versions and updated by Dependabot.
